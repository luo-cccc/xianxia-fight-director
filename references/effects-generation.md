# 特效直接生成：把意图写成当前窗口的画面

本文件用于给视频模型写特效镜头、参考职责和定向返修。效果直接出现在生成视频中；软件名或 Niagara 视觉参考应转译为可见形态、运动与互动，不输出引擎实现或后期制作路线。视觉类型见 [effects-library.md](effects-library.md)，用途、转场与变身选择见 [effects-applications.md](effects-applications.md)。

## 检索目录

- 当前窗口：从起态到终态，只写本段发生的事。
- 完整互动：来源、路径、接点、回应与后果。
- 参考职责：外观、布局、效果、姿态和时序控制分开。
- 并发控制：减少无关变量，保留核心过程。
- 定向返修：按症状改一处，传播到真实依赖。
- 证据与交付：方案、生成、读取和动态观察分别登记。

## 当前窗口里发生什么

先用一句话确定效果的作用，例如“风场把下坠伤员托到桥台，让救援者能抓住他”。再确定这个镜头从哪个阶段开始：风尚未出现、已经接住伤员、还是伤员即将落地。不能每一段都从施术起手重来，也不把下一段的安全落地提前写成本段已经完成。

一条可执行的描述通常包含以下关系，按本场相关性取用，不必输出固定表格：

| 关系 | 要说清什么 | 例子 |
| --- | --- | --- |
| 起态 | 人物、器物、效果此刻在哪，手和支撑是否可用 | 伤员已在桥外下坠，救援者双膝抵住桥沿，右手抓住栏绳 |
| 触发 | 哪个可见动作改变状态 | 救援者左掌向上抬，桥外垂绳先被托起 |
| 发展 | 变化沿什么路径推进 | 伤员衣摆翻起，下坠逐渐减速，身体朝桥台侧移 |
| 互动 | 在哪里接触，双方怎样回应 | 伤员右肩抵到台沿，救援者左手抓住其后领并后移重心 |
| 结果 | 任务完成到哪一步 | 伤员胸腹已压在台面，两人仍需爬离台沿 |
| 留存 | 哪些状态不因效果结束而重置 | 风减弱，垂绳下落；伤员左腿仍不能用力，栏绳仍绷紧 |

写画面，不写抽象评语。“宏大粒子、史诗风场、电影级救援”没有给出上述关系；“风先托起垂绳，再减缓伤员下坠”才指定了可观察进展。招式名和风格名可保留，但去掉后动作仍应成立。

### 时间与跨段

沿用 [continuity-and-timing.md](continuity-and-timing.md) 的成片时码语义。导演记录可以有全场定位，当前窗口提示词只写该窗口的实际进程；JSON 执行文本的时码由既有数值字段定位，不在自由文本重复写一套秒码。

持续效果要继承来源、范围、强弱、已影响对象、在途部分与消耗。术法剩余时间必须有明确起算事件，镜头切换不是新起算点。慢镜说明对应世界动作阶段及同窗各方进度，不能让未入画者额外完成一套动作。

相邻镜同一瞬间的终态与起态共享同一份世界状态；动作与效果均不得重启。若用户要真实时间跳跃、幻境切换或历史重现，明确事件关系并遵守存档契约的能力边界，不用一段含混状态伪装线性连续。

## 完整互动与可见证据

主要效果除了自身好看，还要与人物、目标物或环境发生本场所需的关系。按作用挑选证据，不机械要求每项效果破坏地面、伤人或发光：

- **来源与供给：**液金从臂匣流出，匣内余量变少；召唤从既定入口抵达；无来源“更多一点”容易改写资源条件。
- **路径与范围：**粒流绕过门柱，绳索绕过身体；被墙挡住的路径不能在下一镜无依据完整继续。
- **接触与承力：**兽肩先抵门、腿部再压低、门才离开地面。贴近与接触不是同一件事，特效贴上目标也不等于已经承重。
- **对象回应：**护膜凹陷、伤员减速、断锁分离、手指重新屈伸。这些回应证明效果改变了行动条件。
- **光照与介质：**强光照亮邻近表面，风改变衣发和轻物；普通低亮材料不必强行增加照明，方向由场内来源决定。
- **消退与留存：**流光退去不自动恢复被折断的剑，治疗止血不自动修复旧肩伤；霜、水、碎块与失去的资源继续限制后文。

同一接点上的对抗要保留双方施力与变化。两道亮束在空中相撞，若没有界面偏移、形变、传播受阻或人物调整，就只展示了两条光，不足以说明谁在争夺什么。无需把全部交互同时放在一镜；可以先建立空间，再用当前窗口呈现关键接点，只要用户没有要求不可拆分的连续镜头。

### 真实、主观与表现层

先确定效果属于哪一层。真实藤索可以拦人；幻象藤索是否能碰撞须由规则说明；表现层墨线仅强调挥剑方向时不能突然变成实体。主观体验可以改变声音、颜色或尺度感，客观镜头仍要保持真实人、物与位置。用户若明确要求感知被改写，则另外保留谁相信什么、实际是什么和可回溯线索。

## 参考职责：不让一张图同时锁住一切

有合格素材先复用，只有影响识别、关键形态或连续性的缺口才建议补图。没有参考时按文字原创；“建议帧”只是计划，不代表已经生成或实际查看。

| 素材职责 | 可以控制 | 不能据此默认控制 |
| --- | --- | --- |
| 人物／生物外观 | 已读到的身份、衣饰、器形、轮廓 | 原姿态、当前持物手、未来伤损、整个动作序列 |
| 场景布局 | 地标、通路、尺度参照及已确认关系 | 任意新增出口，或每次换机位就改变世界方向 |
| 效果外观 | 形态、密度、材质、局部运动特征 | 施术者身份、碰撞能力、无限范围或模型实现方式 |
| 起态／中间态／终态图 | 对应瞬间的姿态、部位与接点关系 | 未核实的严格锁帧、两图间任意过程必然可达 |
| 已有短片／相邻帧 | 实际可观察的阶段、方向、速度趋势 | 片外动作、未读音轨、其他片段的一致性 |

每项素材写清来源与控制范围；只有用户路径或描述时，注明尚未读取，不编造五官、纹样或观察结论。参考图固定的站姿与持物不是永久身份锚点，当前窗口按实际动作改变。多张图控制同一维度且冲突时，先沿用户优先级取舍；关键冲突才需要澄清。

图像可上传的数量不证明首尾帧控制或时序多图能力。未核实入口时，使用“外观参考”“中间态目标”等中性职责，不伪造槽位、权重或按钮。只有确认当前模式支持时，才把所选实际帧指定为严格起止条件。平台限制不能让尚未生成的帧被写成已锁定。

必要关键帧钉单一时刻：覆甲图画某一片甲已凝固、另一片仍在铺展，不能一张图同时列完整换装过程。复杂部位对应、穿越接点与承重姿态值得补帧；普通小光点不需要单独资产。完整战斗仍按既有关键转折三帧和段界交接帧规则处理。

## 并发控制：保留核心，减少无关变化

没有通用的“最多几个特效”阈值。风险取决于一段里多少关系要同时正确：多人面孔、手部接点、连续变形、复杂运镜、环境替换和精确同步叠在一起，会让失败来源难以定位。先识别本镜独一份的必要证据，再考虑减少其他变量。

可依次考虑：稳定机位或减少环绕；压低装饰粒子的密度；让旁观者只保持已有状态；删去没有职责的辅助效果；把可独立发生的步骤排成前后顺序；在允许分镜时按完整动作阶段分镜。分镜后起终态仍须连续，每段不能把已经完成的过程再做一次。

**以下不属于同结果简化：**用户要求连续液化，改成烟雾遮住再换外观；要求正面接住巨物，改成画外响声后巨物已经停稳；要求穿越门面，改成人物瞬间出现在另一背景；要求单镜完整过程，偷偷拆成多段。这些方案即使终态相同，也删掉了要求中的过程。

需要简化时，先保留用户指定的主体、关键变化、接点、身份与终态，再调整观察方式。例如把覆甲从绕身环拍改为稳定侧前方机位，减少无关发光纹样，仍让液金完整铺展并定形。若核心过程在已确认限制内确实无法兼顾，写出具体未达项和条件方案，不能声称已经满足原要求。

## 定向返修

实际结果返回后，先定位主要失败是状态、动作、交互、参考职责还是呈现复杂度，再针对证据修改。未观察媒体时以下只能称为预期风险，不写成已经出现的故障。

| 症状 | 先查什么 | 最小改动与需保留项 |
| --- | --- | --- |
| 效果在主体周围随机飘 | 是否缺唯一来源、路径与终点 | 补流向和接入点，保留原人物动作与终态 |
| 前段完成后下段重复起手 | 起态是否仍写“开始施术” | 改为已进行阶段，同步下一镜状态与必要帧 |
| 光很多却没有命中／恢复 | 接点与对象回应是否具体 | 指定接触位置及可见后果，减少遮挡它的装饰 |
| 变身少肢、多肢或部位跳位 | 中间态是否有可追踪对应 | 固定关键关节与姿态，补所需中间帧，保留完整变化 |
| 参考衣服锁住了动作 | 身份参考与姿态参考是否混用 | 把持物和姿势转入当前状态，不重做人脸 |
| 风、投影或倒影方向打架 | 世界方向、机位与光源是否混写 | 先固定来源及地标关系，再换算当前构图 |
| 物品复制、碎片补齐 | 是否漏追踪唯一实体与缺料 | 写明现有数量、位置与缺失，别只加“保持一致” |
| 画面清楚但任务没完成 | 是否只有视觉形态，没有行动结果 | 增加本场必需的承重、通行、握持或信息传递证据 |

一次返修围绕最影响成立的症状组织，保留已经正确的状态。若前段终态、参考或器物归属改变，检查真正依赖它的后段、帧与提示词；边界未变的内容不必全部重做。多次同样尝试没有改善时，改变无关并发或视角，或明确需要的素材，不靠反复堆“绝对稳定”继续。

## 证据边界与验收

方案、文本、生成、观察是不同事实。应分别记录到实际完成的范围：

| 已有证据 | 可以结论到哪里 |
| --- | --- |
| 仅文字与计划帧 | 可以检查任务、变化链、连续性和参考职责；媒体另行生成情况未知 |
| 工具生成成功或用户报告已生成 | 记录其来源；未读取时不评价身份、过程或质量 |
| 已看单张图或抽样帧 | 只评价这些瞬间的外观、接点、尺度、数量与状态 |
| 已观察指定连续片段 | 评价该窗口的动作顺序、持续互动与动态衔接；明确未覆盖窗口 |
| 已读取对应音轨 | 才能评价声源、对白与同步；静音预览不能代替 |

验收应问“任务是否通过可见过程完成”，而不是“出现了多少类效果”。按实际请求检查：核心过程有没有被遮掉；人与物能否从起态到终态；持续效果与代价是否继承；参考只控制被授权维度；复杂度减少后是否仍保留用户要求。结构校验、案例数量、提示词语气和模拟评审不能证明视频模型已成功执行。

## 按用户范围交付

专项任务通常给一句作用说明、必要素材职责、当前窗口可复制提示词、终态及最重要的定向返修点；不强制补整场六件套。完整战斗把这些内容并入已有资产、分镜、关键帧、视频执行稿与审阅摘要，不增加技术制作模块。

可复制提示词重述必要身份与起态，写本段可见过程、接点、光照、声音与终态。内部 FX／APP 编号、素材检索注记、对模型的评价和未来剧情放复制块外。以下为句法示意，实际交付时填好本场内容，不把空模板留给用户：

> 固定侧前方机位。人物与关键器物处于明确起态；可见触发后，主变化沿明确路径推进，与目标在具体位置接触；目标出现对应回应。光照与环境按来源变化，过程结束时保留确定的持物、伤损、支撑和残留。

八个可直接改用的原创短例见 [effects-application-cases.md](../examples/effects-application-cases.md)。它们是未生成的计划稿，不是成功样片或平台能力证明。
