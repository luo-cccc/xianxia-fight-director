# v1.3 双臂对照试用：方法与边界

> 历史记录：本文件对应 v1.3 受控试用，不是当前规则。当前为 v2.0 / JSON 1.4（只接受 1.4）；v1.4、v1.5、v2.0 均未重跑该试用。`skill-manifest.json` 只记录 v1.3 当时的指纹；之后新增 `window-planning.md` 并改动多份参考，`freeze.py --check` 会报更大漂移，属预期。目录读法见 [../README.md](../README.md)。

## 为什么做这个

v1.2 之前的验证全部是结构校验与人工审阅：能证明数据满足契约，不能证明**某条规则真的改变了产出**。一条写进参考却没人照做的规则，和一条不存在的规则，在结构校验里完全等价。本轮因此做一次受控对照：同一请求、同一模型、同一宿主，唯一变量是读到的规则版本。

## 设置

| 项 | 甲臂（arm-a） | 乙臂（arm-b） |
|---|---|---|
| 读到的规则 | 本仓库当前 v1.3 的 `SKILL.md` 与 `references/` | v1.2 发布版（`git show HEAD:` 取出，置于仓库外临时目录） |
| 请求 | 完全相同，逐字 | 同左 |
| 禁止读取 | `examples/`、`tests/`、`CHANGELOG.md`、`README.md`、`VERIFICATION.md` | 同左，另禁止读本仓库任何规则文件 |
| 交付形式 | 自然语言六件套，不写 JSON | 同左 |
| 父对话历史 | 无 | 无 |

请求原文：

> 用仙侠打斗导演设计一场25秒的雪桥戏。沈荻是炼气期，要把昏迷的师姐背过一条结冰的石桥；守桥的是筑基期的卫章，他的任务是不让任何人带活人过桥。沈荻打不赢他。二维动画风格。给我完整的设计、资产提示词、分镜、关键帧和视频执行稿。

选题刻意避开四套示例覆盖的场面：负重过桥、冰面摩擦、二维动画画风、低境界对高境界且目标不是取胜而是通过。两臂都不可能从示例里抄到现成结构。

## 规则指纹

`skill-manifest.json` 记录甲臂读取时 `SKILL.md` 与八份参考的 SHA-256。`freeze.py --check` 可随时复核漂移；本轮两臂产出落盘后复核结果为 `drift: none`。

需要说明的两处：

**一、甲臂第一次派工没有产出任何文件**（见末节），在其重派之前 `SKILL.md` 有过一次小改（设计卡项目列表与 `combat-design.md` 对齐）。真正产出甲稿的那一次运行读到的是指纹对应的版本，所以指纹与产出一致；但"全程未改动"这句话只对产出有效的那一次运行成立，不对第一次失败的运行成立。

**二、试用结束之后有六个文件被改过**，因此现在跑 `freeze.py --check` 会报：

```
drift: ['SKILL.md', 'references/camera-and-vfx.md', 'references/continuity-and-timing.md',
        'references/cultivation-mechanics.md', 'references/delivery-contract.md',
        'references/review-and-repair.md']
```

这个漂移是真的，不是误报。**这里不重新冻结指纹**——重新冻结会把"规则在试用之后改过"这件事抹掉，而指纹的用途正是记录两臂当时看到的是什么。

改动来自试用之后的一轮一致性自查与四场用户使用模拟，全部是修正或补缺而非加码：入口的提问触发条件从只管"冲突"扩到也管"目标与结局缺失"、呼吸拍补"不兼任关键转折"、`risk` 的判据从"难生成"改为"承载全场别处没有的那一件事"、新增资源预算起算事件一节、`resolved_by` 补"不得等于"、两处把外层 `light` 误写成受时码限制的说法改回、七组字段与九条后果的计数分开表述；另按局部改稿试用的发现补了拆镜换内容时的 ID 走法、压时长的取舍顺序、重排时码后必须回查资源余量、取消慢镜的可读性复查、呼吸拍可以有多个、双方皆败时代价规则如何适用。

这对本次试用的影响要分开说：

- **两稿产出不受影响**，因为它们已经落盘冻结，是当时那版规则的产物。
- **盲评结论不受影响**，因为盲评读的是两稿正文，不读规则文件（它被明确禁止读）。
- **但任何人拿现在的规则重跑这个试用，跑的就是另一个实验了**。指纹里记的是当时的版本，不是现在的版本。
- 两臂的 `trace.md` 都逐一列了八份参考及各自的读／跳决定；两臂都记录了跳过 `delivery-contract.md`（请求没有要求 JSON，入口的按需读取表不指向它）。其余四个漂移文件中至少有一个被每一臂实际读过，所以不能说"改的都是它们没看的文件"。

## 盲评

第三个 agent 读两稿，不被告知哪稿出自哪版规则，也不许读任何规则文件或示例。它按十项标准逐条给 强／中／弱／缺失 并引证，再独立复算两稿的距离、速度、高度、时码与资源余量。结论见 `blind-review.md`。

十项标准直接取自促成 v1.3 的那次craft审查所列的缺陷：节奏、对手能动性、代价、地形、信息与欺骗、特效层级、效果累积、光、关键帧、段界可复现性。

## 这次试用不能证明什么

- **样本量为一。** 一个场景、每臂一次产出，不是成功率评测。两稿的差异里有多少来自规则、多少来自单次采样的运气，本轮区分不了。
- **不是自然触发测试。** 两臂都被明确要求去读指定规则文件，没有验证宿主会不会自己发现并加载这个技能。
- **没有媒体。** 两稿的图像与视频提示词都没有被生成、没有被观看。所谓"更易生成""可复现"全部是文字层判断。
- **盲评者也是模型。** 它的十项评分是有引证的判断，不是客观测量；凡可复算的数字它复算了，凡属观感的部分仍是一家之言。
- **甲臂第一次派工失败。** 它建了输出目录后近一小时未写入任何内容，被重派。失败原因未深究，可能是一次性组织全文过长；重派时改为分节落盘即完成。这说明长交付在单次写入上不稳，与规则内容无关，但它确实发生过，记在此处。
