# sim-1 thin request — 作者笔记（摩擦记录）

用户消息全文：「帮我设计一段打戏，两个修士在竹林里打，要好看」。没有世界规则、人物、目的、结局、时长、画风、参考图，也没有后续消息。

## 1. 读了什么、跳过什么

读（7 个）：
- `SKILL.md` 全文。
- `references/combat-design.md` — 目标、优势、攻防因果、动作拍、对手能动性、不可逆代价。本场核心。
- `references/cultivation-mechanics.md` — 只用到「御剑」「符箓/介质」「神识与幻术（虚招那一段）」三节。法相、群战、分身、阵法节点都没展开，本场没有。
- `references/continuity-and-timing.md` — 成片时码、相邻镜逐字共享状态、整镜分段、段界选点。
- `references/camera-and-vfx.md` — 机位、光照归属、效果识别语法、可读性层级、生成风险与保底、导演稿/执行稿分离。
- `references/spectacle-and-style.md` — 记忆画面、招式签名、呼吸拍、镜长等分的指纹、三处硬要求（三帧/交接帧/光照归属）。
- `references/assets-and-keyframes.md` — 稳定锚点与时变状态分离、参考绑定四项、关键帧 role、段界交接帧。

跳过（1 个）：`references/delivery-contract.md`。按需读取表写明「用户明确要求 JSON 存档或导出」才读。用户没要求，我也没出 JSON。**代价**：正文里凡是契约字段名（`cost`、`light`、`risk`/`fallback`、`attrition`、`breath`、`adaptation`、`knowledge`、`role`、`handoff`）我都只能按其他六个文件里的引用去写自然语言对应物。如果评分方期望看到契约字段名或字段级校验，我这儿没有，而且我也无法确认我用的这些名字和契约 1.2 的实际字段是否一致——这是跳读规则的直接后果，不是疏漏。另按指示未读 `examples/`、`tests/`、`CHANGELOG.md`、`README.md`、`VERIFICATION.md`，也没跑 python/测试。

## 3. 像填表而不像做戏的地方

按从重到轻排。

**(1) 生成风险与保底构图 —— 本次最像填表的一项。**
七镜六镜标 `high`。诚实地说，这个字段在这个场景里几乎失去了分辨力：贴地雾＋会动的植物（倒竹、回弹幼竿、内倒竿丛）＋多主体接点，本来就是一次生成很难成的组合，所以老实填就是满屏 high。而 `high` 必须附非空 fallback、`low` 不得附，于是我被迫写了六段保底构图——每段都是「同一世界状态下更省的呈现方式」，加起来接近**第二份迷你分镜**。更尖锐的是：取值只有 `low | high` 两档。这场里 S03（静机位呼吸拍）是真 low，S06（两人分开＋蜡壳＋冷光熄灭）是真的中等——我在 low 和 high 之间来回改了一次，最后标 high 并在摘要里说明。**缺一档「中」，老实的作者只能在过度标注（噪音）和漏标（说谎）之间二选一。** 这是我这次遇到的最具体的规则缺陷。

**(2) 世界状态逐字复用 —— 写了两遍，第二遍纯属誊抄。**
规则要求「相邻镜终态与起态逐字复用同一份世界状态」，执行稿「相邻镜的执行版终态与起态同样逐字共享」。七镜意味着八份状态文本；导演稿写一遍，执行稿按段再写一遍（段内还要再给镜间交界状态）。我最后导演稿用①–⑧编号写一次、执行稿展开成完整文本，**合计抄了约两千字的重复内容**。对一个一句话的需求来说，交付物里占比最大的部分是数据库式的状态誊录，不是编舞。
而且这里有一处真实的自相矛盾：continuity 一边说「复用一份具体世界状态文本，**不另外堆边界 ID**」，一边要求逐字一致。要在一份文档里表达「这两处是同一份」，最省的手段就是给它编号——而编号就是边界 ID。我的处理是：导演稿用①–⑧（当作编辑用的指针），执行稿里一个编号都不写、全部展开成完整文本（因为执行稿必须独立可复制、且规则禁止内部 ID 进提示词）。这是我靠判断补的，规则本身没给出路。

**(3) 关键帧数量。**
硬要求是「每镜至少一张」＋「转折三帧」＋「每个段界一张」。七镜 → 下限 7，加三帧（其中两张可落在本来就要的镜上）、加两张交接帧，我最后写了 12 张，每张含一段 60–120 字的独立静态提示词。对一个没有指定剧情的 34 秒竹林打斗，**十二段提示词是写出来给校验看的，不是给我自己做戏用的**。真正改变了设计的是其中三张（见下条）；其余九张里有五张是把已经写在镜头里的状态再静态化一遍。

**(4) 呼吸拍与段界的耦合。**
「呼吸拍通常是最好的段界」＋「整镜分段」＋「段界要一张可复现交接帧」三条合起来，几乎把分段位置预先决定了：有呼吸拍 → 段界放那儿。本场刚好是三段式、刚好合用，所以不痛。但这是运气：如果一场戏只有一个呼吸拍而需要四段，这三条就会互相打架，规则没说此时该让谁。

**(5) 痕迹规则里那条「至少一项痕迹的来源节拍要在最早的关键转折之前结束」。**
本场只有一个关键转折，而且在 20.2 秒（偏后）。于是这条结构校验**自动通过**——任何一个早期效果都满足它。它对「单一后置转折」的场景没有任何约束力，纯粹是免费分。真正有价值的是它背后那句语义要求（决胜时刻要引用已存在的地形改变），而那一条是不进校验的。

## 4. 真正帮上忙的几条（为对照记下）

- **不可逆支出、分属两方、且要写出「此后限制哪个具体动作」**：这条直接把结局从「谁更强」变成「谁的资源先用完」。代价账目那张表是我先写的，整场动作是从它推出来的。
- **对手能动性里「把反派写成必定打偏就是替他写剧本」**：这一条逼我重做了余波。我第一版是乙「选择不追」——被这条禁掉之后，我必须给一个物理上成立的理由，于是有了「他贴得太低的符把他自己的脚踝也缠住」。这个设计是规则逼出来的，而且比我原来的好。
- **转折三帧（预备/接触/结果）**：这条让我不得不把「决胜接点到底是什么物理动作」想清楚——是掌背被幼竿压在护手翘边上、抽手时割裂。只写接触那一张的话，我大概会停在「剑被压住、她弃剑」这种含糊说法上。
- **光照归属**：确实是免费的戏剧变量。本场的光权弧线（环境 → 乙的符火 → 环境 → 她的剑光 → 乙的符火 → 交回环境）是在写 light 字段时才成形的，不是先有编舞。
- **镜长等分是指纹**：直接影响了 8.5/2.5/3.5/5.5/1.5/4.0/8.5 这个分配。

## 5. 不清楚、自相矛盾或我只能猜的地方

1. **呼吸拍里「没有新攻击」是否包含准备动作？** 我的 B03 里乙抽出最后一张符插进腰带。抽资源算不算「新攻击」？规则只说「不发起新攻击、只让观众看清已发生状态」。**我猜准备≠攻击**，并且把这个动作放在呼吸拍末段。如果判定抽符就算，这条呼吸拍不合格。
2. **镜长等分的判定标准没有给。** 规则只举了 6/6/6/6 和 0–3/3–6 两个例子。我的镜长里 8.5 出现了两次（S01 与 S07）。两个内容完全不同的镜头恰好同长，算不算「等分指纹」？**我猜不算**（因为不是按总时长切出来的，是建立与余波各自需要那么长），但规则给不出判据。
3. **设计卡 300–500 字的软预算与它的必要内容冲突。** 必要项是目标＋规则＋转折＋代价账目＋所知/实际＋终态＋假设。单是代价账目七条（每条要写归属、支出、来源拍、是否不可逆、此后限制哪个动作）就能吃掉大半预算。我超了，规则说是软预算所以不算违规——但一个永远被内容要求顶破的预算，起不到约束作用。
4. **最尖锐的一处：提问机制挂在「冲突」上，而不是挂在「缺失」上。** 工作边界写「只有冲突会改变目标、结局或核心规则时集中询问」。这次用户什么都没给——**没有给定项，就不存在冲突，所以这条触发条件永远不成立**，于是我单方面发明了目标和结局（A1、A5），这是整稿里最重的两条假设。而 SKILL §1 又说「使用用户已给的……不要求先填表」「未给时长时选……并继续」，方向是「别问，往下做」。两条读在一起的结论是：需求再薄也不要问，发明完标成可撤销就行。我按这个做了（交付＋把 A1/A5 放进待核项第 1、2 条，并写明改一条我按影响链重排），但我不确定这是规则的本意还是规则的漏洞。如果本意是「结局这种级别的东西应该问」，那触发条件就该写成「缺失且影响结局」，而不是「冲突」。
5. **参考绑定那两条看起来互相打脸。** 工作边界：「未读图时只继承用户已明确描述的内容，不发明五官、佩饰等参考细节。」assets-and-keyframes：「确需新增造型时单列可撤销设计。」用户这次**什么都没描述**，所以第一条的「已明确描述的内容」是空集；要出资产卡就必须发明外观。我的处理：声明无参考图、全部按文字新设计并标 A4 可撤销、且**不写五官**（只写服装结构、器形、旧疤这类轮廓级锚点）。这个折中是我自己定的；规则应该补一句说明「零描述」时怎么办——现在读起来像是既禁止发明又要求出资产卡。
6. **「不预设媒体未生成」与「本次只完成文本」的口径。** review-and-repair 的证据表里，「只写提示词、没有生成结果」对应「本次仅完成文本；媒体是否另已生成未知」。我照抄了这个措辞。说实话这句话在只有我一个作者、刚写完提示词的场合有点荒谬——我当然知道没生成。但规则明确禁止写成「未生成」，所以我按它写。

## 6. 没能满足的

- **没有 JSON 存档和结构校验。** 用户没要求、按需读取表因此不让我读契约、也不让我跑任何东西（任务也禁止跑测试）。所以所有契约相关的要求（字段名、ID 规则、时间覆盖校验、`cues` 换算）我只能以自然语言近似表达，无法验证是否与契约 1.2 一致。
- **剑速那零点三秒的误差没有消掉。** 南段起点到符位按 6 m/s 算是 8.83 秒，正文把接触写在 8.5–8.9 秒之间。我可以把起点从「身后约四十五米」改成「约四十三米」让它严格对上，但那个数字本身是我设的，改了只是让一个虚构数字更整齐。我选择按「约」记并在摘要里点明——规则要求「凡写『算准』『刚好』的地方复算余量」，我没有任何地方声称算准，所以这是允许的残差，不是隐瞒。
- **没有做媒体观察、图像一致性、画面质量方面的任何结论。** 没有素材可读。
- **「要好看」这个唯一的主观要求，我只能靠记忆画面那一处来兑现**（剑光从她要去的方向压进来、把两人勾成背光轮廓，然后在她松手的同一刻熄灭、光权交回那片她要去的天光）。规则禁止用「震撼、高燃、史诗」这类词交差，所以我把它落成了一个可执行的光照归属变化。这是我最有信心的一处；但必须说清，用户说的「好看」有可能根本是指画风层面的东西（水墨、飘带、慢镜大招），而那条我只能列为待核项 4。
