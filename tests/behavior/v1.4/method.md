# v1.4 独立前向试用：方法与边界

日期：2026-11-08。目标是核对技能是否把特效转成视频模型的当前窗口画面，而非引擎搭建或人工后期任务。

## 输入与运行

一个不继承父对话的新 agent 收到技能绝对路径、五个实际用户请求及独立临时输出目录。未提供预期答案、疑似缺陷、实现方案或评分表。每个请求与完整答复保存在 `case-01.md` 至 `case-05.md`；实际读取范围见 `trace.md`。运行没有调用媒体生成或外部付费工具。

五个请求分别涉及：只交一条 Niagara 式粒子剑阵提示词；独立单人疗伤；右手负伤、左手持剑的连续覆甲与简化；火墙改冰墙的局部更新；人物不移动的水镜观看位置转场。它们是五份真实文字产出，不是既有八例的摘录或人工模拟结果。

这些请求由同一个独立 agent 在一次任务中完成，不是五个独立会话、跨模型实验或成功率测试。没有验证宿主会否自然发现或安装本技能。

## 输入稳定性说明

试用发生在集成期间，未在派发前冻结规则文件字节。读取时，三份新参考已可用，但 `examples/effects-application-cases.md` 尚未落盘；执行者按精确路径与直接父目录核对，保留了缺失记录，继续依据已读规则答复。其后该案例文件完成，类型标题及 FX20 子型也做了最终文字对齐。

`checks.json` 中的文件指纹是最终交付定位，不冒充试用开始时的冻结指纹。最终本地链接另行检查，不改写原始 trace 的历史事实。

## 评阅与工程检查

另一个不继承父历史的 agent 仅收到实际请求／答复及技能路径，按具体要求逐例引证评阅。结果摘要见 `review.md`，未将文字表达称为动态效果通过。

独立代码审查另外发现制作段末项为对象时，旧边界登记路径会抛 TypeError；已增加有效字符串镜头引用检查，并为 1.2／1.3 各类畸形末项补回归。修复后完整套件为 66 个测试方法全部通过；四套示例实际经 CLI 导出并同步七文件。

补充探针从 `make_effect_project()` 递归遍历 `effect_specs` 及首镜 `effect_ids`，逐处替换 None、布尔、零、正负整数、小数、空串、普通串、空列表、空对象、对象列表、NaN、Infinity、超大整数，共 390 次；未出现未处理异常。这不构成组合空间穷尽证明。
