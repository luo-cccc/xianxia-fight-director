# 仙侠打斗导演 · xianxia-fight-director v2.0

一个平台无关的仙侠／玄幻／修仙／修真战斗创作技能。输入剧情、人物、能力、参考素材或已有分镜，交付战斗设计、必要资产及图像提示词、完整分镜、生成窗口规划、定时刻关键帧、通用视频提示词和检查摘要。

它把作品的力量规则转成可见攻防：飞剑何时离手、符箓怎样封路、阵眼如何暴露、法相怎样受限、低境界角色靠什么完成目标。支持近战、远程、御剑、阵法、神识与幻术、法相巨兽、御空追逃、群战，以及变身化形、识海等意识空间的并行动作线、签名特效与特效转场。生成窗口按剧本的关联结构决定，不按平台默认时长切内容。

不固定反杀结构、镜头数量、生成窗口长度、平台时长、灵力百分比或画风。图像／视频提示词是待生成文本，包内不含生成媒体，也不调用外部生成 API。

## 快速使用

安装后可输入：

> 用仙侠打斗导演设计一场30秒的山门救人戏。筑基符修不能打赢金丹守卫，只能用两张符破坏阵眼，让师弟逃走。给我完整资产提示词、分镜、关键帧和视频提示词，三维国漫风格。

也可只修改已有内容：

> 保留角色外观和法宝，取消慢镜，把结局改成双方罢手。检查哪些镜头、关键帧和提示词需要同步更新。

缺少细节时技能会提出少量本场假设，不要求先填一套世界观表；目标与结局缺失或条件冲突时才提问。没有实际读取的图像不能被当作已观察证据。

## 核心要求

编舞：

- **对手能动性**：对手有自己推进的任务，全场至少据已察觉信息变招一次。
- **不可逆代价**：至少一项支出收不回，且分属两方；它限制此后某个具体动作并留在终态。
- **节奏对比**：至少一个呼吸拍，不兼任也不重叠关键转折；镜长按信息量分配，不等分。
- **光照归属**：每镜登记主光来源与归属，转折处易手。
- **决胜三帧与段界交接帧**：关键转折给预备、接触、结果三张静图；段界给一张可复现静图。
- **战场累积**：痕迹至少一项先于关键转折形成，并限制后续路线。
- **所知与实际**：幻术、残影、虚招的信息差单独登记，线索先于识破。
- **生成风险与保底构图**：承载全场唯一信息的镜头预先写好同一世界状态下更省的呈现。
- **数值交叉复算**：速度、消耗、坐标、余量与遮挡交付前独立重算。

特效：

- **特效四问**：谁的、显示什么、花掉什么留下什么、怎么做。按承担的信息分为攻击、防御、位移、计量、规则、状态、空间、环境八组；呈现层效果不接触世界、不留残留。
- **签名特效**：反复出现的效果登记归属、尺度、生命周期、支出与制作路线，跨镜保持同一外观。
- **变身保身份**：前后两套资产共享逐字相同的身份锚点，用世界内遮挡完成切换，节拍为关键转折，代价由变身者支出。
- **飞行保路线**：空域分层，用可见间距交代追逃，下方危险作为终局选择的物理理由。
- **内景保外层不暂停**：识海、梦境、幻阵是并行动作线，每个内景镜头另写同一时刻外层状态。
- **转场默认硬切**：只为需要被记住的跳变登记，写清保留、改变、切点条件与世界内载体。

窗口：

- **按内容定界**：先标关联簇与切点候选，再按用户声明或已核实的平台上限取级；不默认任何时长，不按平台上限切内容。
- **不拆簇**：连续动作、因果链、信息链、形态阶梯、动作线切换、巨物同框与不可逆代价必须同窗；簇超过上限时改设计，不硬拆。
- **切点分级**：A 稳定、B 可藏缝、C 半动作、X 禁止；C 级须写相位、速度、在途物、模糊与声尾，并由后窗承担风险。
- **入口出口与接缝包**：每窗有入口/出口帧；跨界的在途物、术法、计量、代价、所知、光、声、机位、特效阶段、形态与动作线逐项交接。
- **降级阶梯**：高风险窗有可执行的降级切点，切完每段仍在上限内；上限未知时给 30/15/10/6 之类的能力场景，不默认三十秒。

## 安装

将整个技能文件夹复制到下列任意位置，确保 `SKILL.md` 直接位于技能目录中。文件夹必须命名为 `xianxia-fight-director`，与 `SKILL.md` 头部的 `name` 一致；从 GitHub 下载得到的 `xianxia-fight-director-main` 等目录要先改名：

- 项目内：`<project>/.agents/skills/xianxia-fight-director/`
- 用户级：`~/.agents/skills/xianxia-fight-director/`

ZCode 中同名 `.zcode/skills` 的版本优先级更高，已有同名版本时先检查其内容，不直接覆盖。安装后可使用 `/xianxia-fight-director`，或通过仙侠打斗设计、分镜、提示词等自然语言触发。

## 示例与工具

在技能目录执行：

```bash
python scripts/combat_plan.py validate examples/01-sword-and-body.json
python scripts/combat_plan.py export examples/01-sword-and-body.json --out ./my-battle-output
python -m unittest discover -s tests -v
```

`--out` 必须指向不存在的新路径，父目录必须存在；已有文件或目录不覆盖，失败清理本次临时产物。输出统一为 UTF-8 与 LF。

成功只代表 `structural_status: pass`；`semantic_status` 始终为 `needs_review`。校验器只查可由结构证明的后果——三帧齐全且递增、呼吸拍不重叠转折、变招有前因、交接帧归属正确、光照不全同、痕迹先于转折、代价不可逆且多方、信息差成立、高风险有保底；另查动作线归属与按线连续、特效层级与残留相容、变身锚点与节拍、转场相邻且不过密；窗口连续覆盖、关联簇同窗、内部边界有候选、C 级后窗高风险并带降级、入口出口帧对齐且内部共用交接帧、上限与簇跨度、形态不跨界、动作线切换有转场、跨界项进入接缝包。动作是否好看、特效是否被看懂、变身后是否认得出、空间是否可达、平台能否执行，属语义审阅。

**版本**：只接受 `schema_version: "1.4"`。1.0、1.1、1.2、1.3 存档不再兼容，工具直接拒绝；不提供自动迁移，旧稿需按 1.4 字段重写。

五套示例（均为 JSON 1.4，各分三个生成窗口；窗口理由与能力阶梯见各自的 03）：

1. `01-sword-and-body`：法武近战与飞剑离手回防。对手预埋钩口夺剑，虚招配可见线索，光权三次易手；慢镜回召中段只作降级切点。
2. `02-formation-rescue`：利用阵法条件救人脱身，不靠击杀越阶；阵位、水路与撤离路线同属三条关联簇。
3. `03-aerial-avatar`：空中远程斗法、法相尺度与持续术法；法相唯一同框尺度证明不可拆窗。
4. `04-illusion-and-breath`：幻术与神识的信息差。幻修必须骗过神识对物理证据的核对，而不是骗过眼睛；二十八秒也可以是三窗，不因上限三十秒并成一窗。
5. `05-cloud-mind-and-wing`：御剑追逃、识海内景线与云茧遮挡化形。剑身亮度是灵力计量；内景期间外层的身体仍在下降；化形中途被斩茧折翼；三处转场各有世界内载体。示范分层字段与窗口规划。

## 维护

- `examples/*.json` 是工作存档与源；`examples/*/` 是 `export` 生成的六件套与 `project.json`。不要手改导出目录：改 JSON 后重新导出并替换目录，测试会逐字比对。
- 当前回归：`python -X utf8 -B -m unittest discover -s tests`；示例校验：`for f in examples/*.json; do python scripts/combat_plan.py validate "$f"; done`。
- `tests/behavior/` 是历史行为证据，不是当前验收；读法与指纹漂移说明见 [tests/behavior/README.md](tests/behavior/README.md)。
- 修改参考后跑 `freeze.py --check` 会报 v1.3 指纹漂移，这是预期；不要重新冻结历史指纹。
- 提交前确认 `git status` 只包含源 JSON、对应导出文件、脚本、参考与测试，不提交 `__pycache__`、临时导出目录或媒体缓存。
