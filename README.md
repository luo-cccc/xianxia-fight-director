# 仙侠打斗导演 · xianxia-fight-director v1.2

一个平台无关的仙侠／玄幻／修仙／修真战斗创作技能。输入剧情、人物、能力、参考素材或已有分镜，交付战斗设计、必要资产及图像提示词、完整分镜、定时刻关键帧、通用视频提示词和检查摘要。

它把作品的力量规则转成可见攻防：飞剑何时离手、符箓怎样封路、阵眼如何暴露、法相怎样受限、低境界角色靠什么完成目标。支持近战、远程、御剑、阵法、神识与幻术、法相巨兽、御空追逃和群战。

不固定反杀结构、镜头数量、平台时长、灵力百分比或画风。图像／视频提示词是待生成文本，包内不含生成媒体，也不调用外部生成 API。

## 快速使用

安装后可输入：

> 用仙侠打斗导演设计一场30秒的山门救人戏。筑基符修不能打赢金丹守卫，只能用两张符破坏阵眼，让师弟逃走。给我完整资产提示词、分镜、关键帧和视频提示词，三维国漫风格。

也可只修改已有内容：

> 保留角色外观和法宝，取消慢镜，把结局改成双方罢手。检查哪些镜头、关键帧和提示词需要同步更新。

缺少细节时技能会提出少量本场假设，不要求先填一套世界观表。只有决定性冲突才需要澄清。已有设定和素材优先；没有实际读取的图像不能被当作已观察证据。

v1.2将稳定身份与持物、姿态、伤损分开；动作先检查支点、路径和回应，再设计摄影机；环境反馈、风向与巨物尺度按本场需要补充。入口与参考删去重复字段和篇幅说明，不增加必填表。**技能包版本为1.2，工作JSON仍为1.1**，现有数据和CLI兼容。

## 安装

此目录是独立交付包，当前未自动安装。将整个 `xianxia-fight-director` 文件夹复制到下列任意一个位置：

- 项目内：`<project>/.agents/skills/xianxia-fight-director/`
- 用户级：`~/.agents/skills/xianxia-fight-director/`

确保 `SKILL.md` 直接位于该技能目录中。ZCode 中同名 `.zcode/skills` 的版本优先级更高，已有同名版本时先检查其内容，不直接覆盖。

安装后可使用 `/xianxia-fight-director`，或通过仙侠打斗设计、分镜、提示词等自然语言触发。其他宿主是否自动发现 `.agents/skills` 以其自身规则为准。

## 内容

- `SKILL.md`：入口、规则优先级、工作流程、参考文件读取条件。
- `references/`：战斗设计、修炼机制、连续性与成片时间、摄影特效、高燃与画风、资产关键帧、交付契约和修改审阅。
- `examples/*.json`：三套原创完整工作案例。
- `examples/*/`：由相应 JSON 导出的六项 Markdown 交付和项目快照。
- `scripts/combat_plan.py`：可选的结构校验和同源导出工具。
- `tests/`：严格读取、时间引用、分段、关键帧和导出保护的回归检查；`tests/behavior/` 保存受控完整试用及真实局部改稿。
- [v1.2模拟与审查](tests/behavior/v1.2/review.md)：两个独立用户场景、一次局部改稿、实际纠错及自问自答，保留输入和正文。
- `CHANGELOG.md`：v1.2采纳与删减记录、历次修复对照。
- [GITHUB_RESEARCH.md](GITHUB_RESEARCH.md)：2026-11-04的相似GitHub项目检索与对比。
- `sources.json`、`THIRD_PARTY_NOTICES.md`：历史七个参考包，以及本次四项GitHub方法参考的采用方式、读取指纹与文件映射。

普通聊天不需要 Python 或 JSON。脚本需 Python 3.10+，只使用标准库。

## 示例与工具

在技能目录执行：

```bash
python scripts/combat_plan.py validate examples/01-sword-and-body.json
python scripts/combat_plan.py export examples/01-sword-and-body.json --out ./my-battle-output
python -m unittest discover -s tests -v
```

`--out` 必须指向不存在的新目录，父目录必须存在；已有文件或目录不覆盖。导出前验证并在内存生成文档，失败清理本次临时产物。在 Windows 以目录重命名发布；在 POSIX 先独占创建目标目录再移动文件，失败时清理，因此 POSIX 发布过程不是单步原子可见。

成功只代表 `structural_status: pass`；`semantic_status` 始终保留 `needs_review`。媒体观察由作者按真实来源登记，脚本不会推断是否生成、是否观看或观察结果通过。JSON 可表达动作并行与跨镜承接，不能自动证明空间可达、动作耗时、图像一致或平台能执行。

v1.1把完整导演稿（`03-storyboard.md`）与精简执行稿（`05-video-prompts.md`）分开：执行稿只含本段所需规则和资产、当前镜头动作及段内时码，不重复完整跨镜起手、全场未来结局或内部依赖。作者必须填写当前镜头的`execution.cues`，不能让程序用正则截取旧动作正文。所有JSON时间为成片时间；精确事件/呈现双时轴、重放与插叙不在本版支持范围。

v1.0工作JSON需按[交付契约](references/delivery-contract.md)人工补写窗口执行文本并升级为`1.1`；旧JSON会被明确拒绝，不自动重写自由文本。旧ZIP保留以便回溯。

三套示例：

1. `01-sword-and-body.json`：法武近战与飞剑离手回防。
2. `02-formation-rescue.json`：利用阵法条件救人脱身，不靠击杀越阶。
3. `03-aerial-avatar.json`：空中远程斗法、法相尺度与持续术法。

完整字段和时间规则见 [交付契约](references/delivery-contract.md)。局部改稿流程见 [审阅与修改](references/review-and-repair.md)。实际测试结果见 `VERIFICATION.md`。
